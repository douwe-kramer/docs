## Create the authorization

```http
POST /v1/mandates/{mandate_id}/authorizations
Authorization: Bearer att_test_...
Idempotency-Key: auth_01J...
Content-Type: application/json
```

```json
{
  "external_reference": "booking_91823",
  "proposed_action": {
    "action": "booking.create",
    "attributes": { "city": "Amsterdam", "check_in": "2026-11-02" },
    "payment": { "amount": 39900, "currency": "EUR" }
  },
  "execution_window_seconds": 300,
  "commitment": "sha256:<64 hex characters>"
}
```

The commitment is `sha256:` followed by the hex SHA-256 of the domain line `attesso:authorization:commitment:v1` plus a newline, concatenated with 32 random bytes (the opening). Keep the opening server-side and reveal it only at commit. A commitment cannot be reused within an Organization.

The response is the durable record. Gate on its three values, not on the HTTP status:

```json
{
  "id": "aut_...",
  "mandate_id": "mnd_...",
  "decision": "ALLOW",
  "state": "RESERVED",
  "can_execute": true,
  "reason": { "code": "POLICY_MATCH" },
  "execute_before": "2026-10-18T09:13:06Z"
}
```

A refusal is also `201`, with `decision: "DENY"`, `state: "DENIED"`, and `can_execute: false`. `reason.violations[]` names the path and the policy code. The codes are listed on [Errors and idempotency](/reference/errors-and-idempotency#authorization-decisions).

A Mandate has one reservation in flight. A second authorization while one is `RESERVED` is denied with `MANDATE_UNAVAILABLE` and creates no reservation.

## Gate execution

Execute only when the latest Authorization has all three values:

```json
{
  "decision": "ALLOW",
  "state": "RESERVED",
  "can_execute": true
}
```

Start and finish before `execute_before`, and ensure any external credential cannot act after that deadline.

## Commit after acceptance

Commit means the external executor accepted the action. It does not mean a card was created, a payment settled, or a service was fulfilled.

```http
PUT /v1/authorizations/{authorization_id}/commit
Authorization: Bearer att_test_...
Idempotency-Key: commit_...
Content-Type: application/json
```

```json
{
  "external_action_reference": "booking_91823",
  "provider_transaction_reference": "provider_77401",
  "reported_accepted_at": "2026-08-10T03:02:41Z",
  "opening": "<64 hex characters>"
}
```

The `opening` must open the `commitment` recorded when the authorization was
created; otherwise the commit is refused and nothing is recorded.

A successful commit atomically changes the Authorization to `COMMITTED` and its Mandate to `CONSUMED`. The response is the Authorization in its committed state:

```json
{
  "id": "aut_...",
  "state": "COMMITTED",
  "decision": "ALLOW",
  "can_execute": false,
  "external_action_reference": "booking_91823",
  "committed_at": "2026-10-18T09:12:00Z"
}
```

For the full pattern of taking an `ALLOW` and executing it on your own payment
provider, see [bind an authorization to your PSP](./bind-to-your-psp).

## Cancel only when execution is impossible

Disable every external card, token, job, or provider capability before calling the cancellation endpoint. Cancelling does not refund a recurring period's consumed budget: `current_period.consumed_amount` keeps counting the cancelled reservation.

```json
{
  "reason": "EXECUTION_FAILED",
  "execution_disposition": "NO_LONGER_POSSIBLE",
  "external_credential_reference": "vcc_opaque_481"
}
```

Use `NEVER_BECAME_POSSIBLE` only when no external capability was ever usable.

Cancellation is outcome-idempotent: cancelling an Authorization that is already
`CANCELLED` succeeds and returns the same state; nothing is released twice.

## Resolve an uncertain response

<Steps>
  <Step title="Stop new execution">
    A timeout or `503` never grants permission. Do not start another action.
  </Step>
  <Step title="Read current state">
    Retrieve `GET /v1/authorizations/{authorization_id}`.
  </Step>
  <Step title="Replay the same operation">
    If still appropriate, retry with the same idempotency key and identical body.
  </Step>
  <Step title="Escalate terminal conflicts">
    A committed, cancelled, or expired Authorization cannot transition again.
    A commit against an Authorization that is no longer `RESERVED` fails with
    `409` (`RESOURCE_STATE_CONFLICT`, `retryable: false`): re-read the state and
    reconcile instead of retrying.
  </Step>
</Steps>

When the outcome is ambiguous, follow the [reconciliation decision table](./reconcile-authorizations)
before committing or canceling: a timeout is not proof the provider did nothing.
