This is the shortest complete server-side integration path, running on the free
test environment. Use the test API at `https://api-staging.attesso.com` with an
`att_test_` key. The live environment at `https://api.attesso.com` requires
`att_live_` keys, which are enabled only after linking Stripe Billing.

## Run it end to end

One command goes from a test key to verified evidence on your own machine: it
creates the Mandate, approves it in the browser with a passkey, shows one
over-cap attempt refused, commits one in-cap action, and verifies the signed
evidence locally. Node.js 20+, no dependencies.

```zsh
curl -O https://raw.githubusercontent.com/douwe-kramer/docs/main/examples/quickstart.mjs
node quickstart.mjs
```

First run: paste your `att_test_` key once and save the three printed
approval-trust values in the dashboard once; every later run is zero-config.

<Warning>
  Never expose an Attesso API key to a browser, end user, or agent.
</Warning>

## The five calls, if you assemble it yourself

1. `POST /v1/mandates`: create the Mandate (`PENDING_APPROVAL`) with its policy, window, and approval deadline.
2. `POST /v1/mandates/{id}/approval-sessions`: sign a short-lived identity
   assertion and create the hosted approval session; send the browser to the
   returned `approval_url`, then read the Mandate server-to-server until it is
   `ACTIVE`. Claims and signing examples: [Hosted approval](/guides/hosted-approval).
3. `POST /v1/mandates/{id}/authorizations`: authorize the concrete action;
   continue only when `can_execute` is exactly `true`.
4. `PUT /v1/authorizations/{id}/commit`: after your executor accepts the
   action; the Authorization becomes `COMMITTED` and the Mandate `CONSUMED`.
5. `GET /v1/mandates/{id}/evidence`: fetch the signed bundle and verify it
   ([Verify evidence](/guides/verify-evidence)).

Use one idempotency key per logical write; reuse it only when retrying the
same operation with the same input.
